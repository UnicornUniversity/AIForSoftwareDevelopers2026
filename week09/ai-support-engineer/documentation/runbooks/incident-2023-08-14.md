# Post-mortem: 2023-08-14 — Portal partial outage after hotfix rollback

**Severity:** 1 (customer-visible; ~28 min portal login broken)
**Duration:** 21:04 – 21:32 CEST
**Author:** Tomáš H.
**Reviewed:** 2023-08-17 at Ops weekly

## TL;DR

An engineer applied a hotfix to the customer portal via
`kubectl edit deployment` during an outage. ArgoCD, which owns the app,
noticed drift and reverted the fix. Login was broken for another 8 minutes
until the engineer realized what was happening.

## Timeline (CEST)

- **20:47** — First alerts. `EdgeNginx4xxRate` > 10% on `portal.pchosting.cz`
- **20:52** — On-call Tomáš begins investigation. Confirms 500s from
  portal-api pod logs.
- **20:57** — Root cause identified: broken Redis DSN in ConfigMap after
  earlier merge. Tomáš writes fix.
- **21:04** — Applies fix via `kubectl edit deployment portal-api -n prod-portal`.
  Requests succeed for ~3 minutes.
- **21:11** — Requests start failing again. Tomáš confused; re-checks
  Redis DSN — it's back to the broken value.
- **21:19** — Realizes ArgoCD is auto-syncing the deployment. Application is
  in "auto-sync" mode with self-heal on.
- **21:22** — Disables ArgoCD auto-sync temporarily. Re-applies fix.
- **21:28** — Fix persists. Login recovery confirmed.
- **21:32** — All customer-visible errors cleared.

## Root cause

1. Original bug: ConfigMap edited manually (bypassing git → ArgoCD) with a
   typo in the Redis DSN.
2. During the fix: ArgoCD is authoritative. Any live edit to a deployment
   ArgoCD manages will be reverted on the next sync tick (default 3 min).

## Contributing factors

- No documented procedure for "hotfix while ArgoCD manages the resource".
- No `#incident-active` channel discipline yet — the on-call was working alone.
- ArgoCD auto-sync + self-heal is enabled by default on prod apps, which is
  usually what we want, but is footgun-shaped during incidents.

## Corrective actions

- [x] Add hotfix procedure to [docs/03-deployment-guide.md](../docs/03-deployment-guide.md)
- [x] Ban `kubectl edit` in prod (linting via OPA Gatekeeper)
- [x] Runbook update: incident procedures now require a dedicated `#incident-active`
      channel per incident (implemented Sep 2023)
- [ ] ArgoCD self-heal should be disabled during declared sev-1 incidents.
      Automation ticket OPS-2044 — not yet implemented as of 2024

## Lessons

- ArgoCD reconciliation is a feature, not a betrayal. Design incident
  procedures around GitOps, not against it.
- Working alone during a sev-1 is a smell. Always page a second pair of eyes.
